# 真机核验清单

本文件列出**只能在真设备上确认**的项——离线环境（DNS 污染、无 Android 设备、
无真实相册）覆盖不到，而它们又都是「代码看起来对、用户那里就是不行」的类型。
每条都写清：对应哪个审查条目、怎么操作、期望看到什么、失败了先看哪里。

建议节奏：每次发版前跑一遍与本次改动相关的行；改动集中在引擎/网络时至少跑
「二、站点与引擎」整节。勾选框请连同日期一起记在 release issue 里。

---

## 一、平台行为（与站点无关，任何能上网的环境都能测）

### D1 Android 8/9 相册权限（H1）
**环境**：API 26/28 模拟器或真机（Android 10 也值得跑一次）。
1. 全新安装 → 打开任一站点 → 点任意帖子的下载。
2. 首次下载应当弹出系统存储/相册授权弹窗（此前从不弹，直接 ACCESS_DENIED）。
3. 允许 → 图片出现在系统相册，且下载记录多一条。
4. 拒绝 → 提示是「没有相册写入权限…」这句可读文案，而**不是**「下载失败」；
   随后去系统设置里授权、回到应用再点下载，**应当立刻成功**（拒绝不会被永久缓存）。
**失败先看**：`lib/foundation/util/image_downloader.dart` 的 `_ensureGalleryAccess`。

### D2 批量下载的取消与去重（M11/M12）
1. 多选 20+ 张 → 批量下载 → 中途返回上一页（页面销毁）。
2. 后台不应继续拉文件（日志里不再出现新的下载请求）。
3. 对同一帖连点两次下载：第二次应提示「已保存过，本次跳过」，相册里**只有一张**。
**失败先看**：`home_content.dart` 的 `_batchCancelToken`、`image_downloader.dart` 的 `_alreadySaved`。

### D3 自定义下载目录被拒（M7）
1. 设置 → 下载 → 选择目录 → 选一个公共目录（如 `/storage/emulated/0/Download`）。
2. 在 Android 10+ 的 scoped storage 下不可写时，应当**当场拒绝并提示换一个目录**；
   可写时正常保存，随后下载落到该目录。
**注**：探针结果只缓存「成功」，失败后换目录会重新探测。

### D4 视频退后台暂停（M19）
1. 打开一个视频帖播放 → 切到后台（Home 键）。
2. 声音应当立即停止；回到前台且此前在播 → 自动续播；此前手动暂停 → 不应自己播起来。

### D5 查看器放大后不再被「下滑关闭」劫持（M29）
1. 打开图片 → 双指放大到 2x 以上 → 单指上下拖动。
2. 应当是平移图片，**不是**关闭查看器；缩回 1x 后下滑关闭恢复。

### D6 黑名单改动后瓦片不串图（H4）
1. 首页记下某位置瓦片的图 → 去黑名单加一个能命中当前可见列表的标签 → 返回首页。
2. 同一位置的瓦片不能显示改动前那帖的图（此前因 Sliver 按 index 复用 + gaplessPlayback）。

### D7 备份导出与导入（H6）
1. 设置 → 备份 → 导出：应当**弹出系统分享面板**（而不是只写进一个要 ADB 才能取的私有目录）。
2. 导出的 JSON 里能看到 8 段：settings / servers / blockedTags / favorites /
   searchHistory / downloads / history / hosts，且**不含** apiKey / login。
3. 导入同一份文件两次：收藏、下载、浏览历史不翻倍；搜索历史合并不丢现有条目；
   每段都有 `ok/总数` 的汇报；含坏记录的文件只跳过坏记录。

## 二、站点与引擎（需要能直连这些站点；本开发环境对它们有 DNS 污染）

### D8 danbooru / e621 四档评级（H3）
1. danbooru：分别搜索 `rating:g` 与 `rating:s`，各取一条。
   **期望**：`g` 档在 UI 显示**绿徽章（安全）**；`s` 档显示**可疑徽章**。
2. 在「安全」筛选项下浏览：拉到的应当是 general 档（`rating:g`），不是 sensitive。
3. e621 同样跑一遍（`rating:g` vs `rating:s`）。
**失败先看**：`normalizeRatingFourTier` 与两个仓库的 `ratingMapFourTier`。

> 顺带核对 danbooru 的 `/posts.json` 是否仍返回 `uploader_name`：解析器对缺失是
> 容忍的（回 null），但这个字段被测过——若站点已移除，fixture 与相关口径要一起收掉。

### D9 zerochan 大图（M1）
1. 打开 zerochan 站点，点开一条帖子的查看器。
2. **期望**：能看到大图（不是只有缩略图）。实测列表响应不含 `file` 字段，
   如果只有缩略图，说明需要补「详情页解析大图」这条路径——这正是 M1 待定项。
3. 顺手确认解析出的地址确实可用（复制到浏览器能打开）。

### D10 rule34 / safebooru 的标签建议（M2）
1. 搜索框输入两个字母，观察是否出现标签建议。
2. 若没有：看日志里 `[Rule34Repository] tag 建议响应非预期形态：…` 那行，
   它现在会打印收到的形态（类型/长度/前 120 字），据此决定是否换端点。

### D11 sankaku 是否被 Cloudflare 挡（M4）
1. 添加 sankaku 站点 → 打开首页。
2. **期望**：能出图（浏览器 UA 放行）。若 403，日志里会有明确状态码。

### D12 探测与并行加站（OPT 2.6 / M25）
1. 服务器 → 添加 → 输入一个站点 URL → 探测。
2. **期望**：秒级出结果（此前串行最坏 150 秒）；取消按钮在探测中可用，
   连点开始不会并发两次；取消后按钮置灰到当前探测返回为止。

### D13 站点家族模板（H5）
1. 添加 gelbooru.com → 回到服务器页：Xbooru / Realbooru / TBIB / Rule34.us 四个
   模板仍应显示「可添加」（不再因为同为 gelbooruV2 引擎而全变「已添加」）。
2. 对已添加的那条点「编辑现有」：打开的应当是 **baseUrl 完全相同**的那个站点。

### D14 探索 / 图集的分页与黑名单（M27）
1. 探索页三个 Tab 各自滚到底：应当继续加载（此前只有一页 60 条）。
2. 从探索页或图集详情页进入的帖子，若命中黑名单应当被过滤掉（与首页同口径）。
3. 切换站点后，探索/图集/图集详情应当重拉（不残留上一个站点的内容）。

### D15 hosts 映射与证书（回归）
1. 设置 → Hosts → 加一条 `1.2.3.4 your-board.example.com` → 启用。
2. 请求该域名时仍能完成 TLS 握手（映射只换连接 IP，不改 Host/SNI）。
3. 输入非法条目（单标签域名 / 非 IP）应被拒绝并提示。

## 三、Play 版（零预置 BYO）

### D16 空白客户端首启（OPT §1）
用 `--dart-define=boorunova.play=true` 构建并安装：
1. 首启引导**不应**出现任何站点列表，而是「自己添加第一个服务器」入口。
2. 服务器页「热门站点」区整体消失；添加站点只能手填 URL + 探测。
3. 引擎下拉里是中性名（`Danbooru API` / `DAPI JSON board` …），不出现站点名。
4. 关于页没有 GitHub 外链。
5. 手动添加一个站点后，浏览/搜索/收藏/下载/备份全部照常可用。
6. **安全模式默认开启**：首页 / 探索 / 图集的首屏都不应出现限制级内容；
   设置 → 隐私 → 「内容来源与举报」页里安全模式为开。
7. 在该页关掉安全模式：应当先弹**本地年龄确认**；取消则保持开启，确认后关闭且
   首屏恢复不限评级。确认状态只存本机。
8. 「内容来源与举报」页能列出你添加的服务器，点一条用浏览器打开该站
   （用于站内举报）；屏蔽入口与申诉说明都在同一页。
**注意**：GitHub 直装版（不带该 dart-define）安全模式默认**关闭**，行为与以前一致。

### D25 未完成下载的续跑（OPT §3.3）
1. 多选十几张开始批量下载，进度走到一半时**杀掉进程**。
2. 重新打开 App：首页应弹出「有未完成的下载（N 个），要继续吗？」。
3. 选「继续」：应开始下载，且**已下过的部分不重下**（抓包能看到 `Range:`；
   本地目录里之前留下的 `.part` 会消失、最终文件正常进相册）。
4. 再重复一次，这次选「忽略」：不再打扰，队列被清空（再重启也不弹）。
5. 全部下完后再重启：**不应**弹出任何提示（成功的条目在完成时已出队）。
6. 跨重启时间超过 7 天的旧条目不再提示（与 `.part` 保鲜期同一口径）。

### D24 快捷屏蔽（OPT §5.5）
1. 打开一条帖子的**详情页**，长按任意标签：应弹出「屏蔽这个标签？」并给出
   「全局屏蔽 / 仅 <站点名> / 取消」三个出口。
2. 选「仅本站屏蔽」→ 返回首页：该标签的帖子在本站消失；切到**另一个站点**，
   同标签的帖子应当照常出现（作用域没串）。
3. 选「全局屏蔽」→ 两个站点都不再出现该标签。
4. 取消 → 什么都不发生（黑名单页不应多出条目）。
5. 顺带确认：单点标签仍然是「选中」（批量屏蔽/搜索那条老路径没被长按抢走）。

### D23 断点续传（OPT §3.1）
1. 选一张大图（几 MB）开始下载，中途**杀掉进程**（或断网让下载失败）。
2. 下载目录里应留下 `<文件名>.part`，**没有**最终文件、相册里也没有半截图。
3. 恢复网络后重新下载同一张：抓包/日志应看到 `Range: bytes=<已下载长度>-`，且
   服务端回 `206`；完成后 `.part` 消失、最终文件可正常打开、相册里只有一张。
4. 找一台**不认 Range** 的源（回 200 整份）：结果必须是完整的一份内容，
   **不能**出现「新旧内容拼在一起」的损坏文件。
5. 用户主动取消下载：`.part` 应保留（下次续传的起点），且不产生最终文件。

### D22 自建站 / 非预置域名的类型探测（OPT §2.6、AUDIT M3）
1. 准备一个**非预置域名**的 booru（自建 Danbooru/Gelbooru 实例，或某个镜像站）。
2. 「添加服务器」粘贴地址 → **引擎类型应被自动识别**，而不是停在「未知」。
3. 为什么必须真机验：域名捷径只覆盖 10 个预置域名；非预置域名完全依赖
   「按类型探测」。此前 JSON 响应被 dio 解成对象、特征串（`"preview_url"` 等）
   永远匹配不上，探测对所有 JSON 引擎静默失效——本地纯函数测试喂的是原始
   字符串，看不出这个问题。
4. 同时观察耗时：应当是「秒级」，不应出现十几秒的等待（新加了优先级早退）。

### D21 预览画质与站点默认排序（OPT §6.4）
1. 设置 → 下载 → 「预览画质」切到**原图**：打开查看器应真的加载原图
   （比 sample 明显更大更清晰；大图加载变慢是预期的）。切回预览后重开应回到 sample。
2. 站点偏好 → 预览画质设为原图：**只影响该站点**的查看器与详情页头图。
3. 站点偏好 → 默认排序设为「按日期」：打开搜索页时排序已预选「按日期」；
   在页内改成别的排序并返回后，再打开仍以站点默认为准（站点默认是初值，
   不覆盖当次选择）。
4. 大图加载失败/超时时不应白屏（与既有图片加载路径同口径）。

### D20 站点作用域黑名单（OPT §6.4）
1. 设置 → 黑名单：作用域下拉选「全局（所有站点）」，添加 `test_tag`。
2. 再选某个站点，添加同一个 `test_tag`：**应当各留一条**（此前只按名字去重，
   这一步会被静默吞掉）。列表里两条分别显示「全局」与「仅 <站点名>」。
3. 只在 A 站屏蔽 `cat` 后：A 站的列表不再出现 `cat`，**B 站照常出现**。
4. 删掉 A 站这个服务器：作用域下拉里不应再残留它；已有条目的作用域文案
   退化成显示 id（不崩、不丢数据）。

### D19 站点健康面板（OPT §5.4）
1. 服务器页右上角的心跳图标 → 「检查全部」：每条站点出现状态点与延迟；
   检查中显示转圈（点单个站点的状态点只重查它）。
2. 故意加一个不存在的域名：应在 **8s 内**显示「连不上」，而不是一直转圈。
3. Cloudflare 保护的站点：若显示「被拒绝（403/401）」，说明探测请求头与真实
   请求不一致（应当带同一个 UA 与 hosts 拦截）——这是要查的 bug，不是站点问题。
4. 打开 hosts 映射并为某站点配映射：该条应出现 hosts 徽章；关掉总开关后消失。
5. 观察流量：健康检查只取响应头，检查几个站点不应产生可感知的流量消耗。

### D18 站点级偏好（OPT §6.4，只能真机确认的部分）
1. 设置 → 服务器 → 某站点 ⋮ → **站点偏好**：
2. 把「可见评级」设为「可疑」，回到首页——**当前浏览应当立刻按新评级重拉**
   （不是要再搜一次才生效）。
3. 从该站点的 ⋮ → 编辑，改一下名字保存，再进「站点偏好」：
   **刚才设的评级 / 画质 / 子目录都还在**（回归点：编辑器曾把不在表单里的字段重置）。
4. 设「下载子目录」为 `danbooru`，下载一张图 → 文件应落在
   `<全局下载目录>/danbooru/` 下（相册里能看到，下载记录的路径也含该子目录）。
5. 把子目录填成 `../x`：输入框应当**当场报错**，不保存该值。
6. Play 版再验一次第 2 步：安全模式开启时，把可见评级设成「全部」
   → 实际仍只取安全档（合规口径不可被站点设置放宽）。

### D17 targetSdk 35 的边到边行为（OPT §1.4，上架前做）
1. 把 `android/app/build.gradle` 的 `targetSdkVersion` 显式提到 35 后构建。
2. Android 15 上检查：状态栏/导航栏区域是否被内容遮挡、手势区是否可用、
   沉浸式查看器与全屏视频是否正常。
3. 这一步会**改变视觉与手势行为**，必须真机确认后再决定是否随 Play 版发布。
